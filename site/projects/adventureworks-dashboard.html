Completed course · Guided Power BI project

Retail Sales & Returns Dashboard

After completing Maven Analytics' Power BI course, I built a multi-page dashboard with the AdventureWorks sample dataset to explore sales performance, product and customer patterns, returns, and targets.

Power BI · Power Query · DAX · Data modeling · Interactive reporting

Project context: Shreejita completed Microsoft Power BI Desktop for Business Intelligence by Maven Analytics and built this dashboard as a guided course project. The supplied PDF is a copy of the Udemy course listing, not a completion certificate. The project description below reflects report pages and transformations visible in the screenshots.

Business questions explored

  • How are revenue, profit, order volume, and return rate changing over time?
  • Which product categories and individual products contribute most to orders and revenue?
  • How do customer groups differ by order behavior and revenue?
  • Where do returns, targets, and product-level performance deserve closer attention?

What the report contains

The report includes an executive overview, product and customer detail pages, a map, and exploratory Power BI pages such as a decomposition tree and key influencers. The executive view brings headline KPIs together with a monthly revenue trend, orders by category, and a product table that compares orders, revenue, and return percentage. The product page includes target comparisons, adjustable price scenarios, profit views, and return trends. The customer page explores customer counts, revenue per customer, and customer segments.

The executive page emphasizes revenue, profit, order volume, and return rate, alongside category comparisons, monthly trends, and product-level return indicators. Numerical outputs are omitted here because the underlying dataset cannot be shared publicly.

What I built

I used Power Query to prepare and reshape the source tables, organized the sales and returns data with customer, product, calendar, and territory lookups, and created DAX measures for the report's core performance indicators and time comparisons. I then assembled the measures into linked report pages with filters and visual interactions.

  • Combined sales files and applied data types, column selection, and other Power Query transformations.
  • Added calendar attributes such as day name, month, quarter, year, and period start dates.
  • Cleaned and enriched customer and product lookup tables, including derived customer and pricing fields.
  • Reshaped a product-category sales example by unpivoting and pivoting regional values.
  • Modeled sales and returns alongside calendar, customer, product, and territory lookups.
  • Created measures for revenue, profit, orders, returns, return rate, previous-month and year-to-date results, rolling revenue, and target gaps.

The course provided instruction and a project framework; the work above describes Shreejita's implementation of that exercise and does not imply that the underlying dataset or project brief was original.

What I learned

The project brought together the main stages of a Power BI workflow: shaping source tables, connecting dimensions to transaction data, defining reusable measures, and arranging interactive pages around business questions. It also made the importance of clear metric definitions and focused page design visible: a report can contain many analyses, while the opening page still needs to make its most useful story easy to scan.

Data, files, and sharing

The dashboard uses AdventureWorks training data. The PBIX file, raw CSV files, screenshots containing data, numerical results, and customer-level details are intentionally not included in this public case study. The narrative is based on supplied screenshots rather than an independent inspection or validation of the Power BI model.
